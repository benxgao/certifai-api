# QuizQuestion-Exam Association Constraint Implementation

## Overview

This document outlines the implementation of the constraint that ensures a quiz question can only be associated with an exam when the question's `generated_from` value equals the exam ID or is null (for general questions).

## Schema Changes

### QuizQuestion Model

- Added foreign key relationship between `generated_from` and `ExamAttempt.exam_id`
- Added index on `generated_from` for performance
- Added `generatedFromExam` relation field

### ExamAttempt Model

- Added `generatedQuestions` relation field to track questions generated specifically for this exam

### Database Constraints

- **Relational constraint**: `QuizQuestion.generated_from` references `ExamAttempt.exam_id`
- **Application-level constraint**: Questions can only be associated with exams where:
  1. `question.generated_from` is `null` (general questions), OR
  2. `question.generated_from` equals the exam's `exam_id` (exam-specific questions)

## Implementation Details

### 1. New Validation Utility (`questionExamConstraint.ts`)

Created comprehensive validation functions:

- `validateQuestionExamConstraint(questionId, examId)`: Validates single question-exam association
- `validateMultipleQuestionsExamConstraint(questionIds, examId)`: Validates multiple questions at once

**Validation Rules:**

- Question and exam must exist
- Question and exam must be for the same certification
- Question's `generated_from` must be `null` OR equal to the exam ID

### 2. Updated Question Association Logic (`examQuestionAssociation.ts`)

Enhanced the `associateQuestionsWithExam` function to:

- Import and use the validation utility
- Validate all selected questions before association
- Return detailed error messages for constraint violations
- Prioritize exam-specific questions over general questions

### 3. Answer Submission Validation (`answerUserExamQuestions.ts`)

Added constraint validation to the answer submission endpoint:

- Validates question-exam association before allowing answers
- Returns appropriate error messages for constraint violations
- Prevents users from answering improperly associated questions

## Business Logic

### Question Selection Priority

1. **Exam-specific questions** (`generated_from = exam_id`): Highest priority
2. **General questions** (`generated_from = null`): Secondary priority
3. **Other exam questions** (`generated_from != exam_id`): Excluded

### Use Cases Supported

- **Exam-specific questions**: Generated by AI for a particular exam, only usable in that exam
- **General questions**: Pre-existing questions that can be used in any exam for the same certification
- **Cross-exam isolation**: Questions generated for one exam cannot accidentally be used in another

## Error Handling

### Validation Errors

- Clear error messages indicating constraint violations
- Detailed logging for debugging purposes
- Graceful degradation when validation fails

### Example Error Messages

- `"Question was generated for exam {exam_id} and cannot be used in exam {different_exam_id}"`
- `"Question and exam are for different certifications"`
- `"Question-exam constraint validation failed"`

## Benefits

1. **Data Integrity**: Ensures questions are only used in appropriate exams
2. **Exam Isolation**: Prevents accidental cross-contamination of exam-specific content
3. **Flexibility**: Supports both exam-specific and general questions
4. **Performance**: Optimized with database indexes
5. **Debugging**: Comprehensive logging and error messages

## Testing Considerations

### Test Scenarios

1. Associate exam-specific question with correct exam ✅
2. Associate exam-specific question with wrong exam ❌
3. Associate general question with any exam ✅
4. Associate questions from different certification ❌
5. Answer question properly associated with exam ✅
6. Answer question improperly associated with exam ❌

### Database Consistency

- Questions generated with `generated_from = exam_id` can only be used in that exam
- Questions with `generated_from = null` can be used in any exam (same certification)
- Foreign key constraint ensures referential integrity
